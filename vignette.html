Introduction

UMAP stands for Uniform Manifold Approximation and Projection and has two main functions. The first way UMAP can be used is as a non-linear dimension reduction technique. The second way UMAP can be used is as a way to visualize high-dimensional data.

Quick Introduction to Riemannian Manifolds

Linear methods for dimension reduction assume that the data lies on a flat or linear subspace. On the other hand, nonlinear methods like UMAP assume that the data lies on a Riemannian manifold. A manifold is a shape that appears to be flat when zoomed in on, but not strictly flat overall. An example of this is a ball, where if you were to take a microscope and zoom in closely, the shape appears to be flat even though we know the overall shape isn’t. Riemannian means that the shape comes with a built-in rule to measure the distances and angles on its surface. Combining these terms together, we get the definition that a Riemannian Manifold is a shape that appears to be flat when zoomed in on that has a built-in rule to measure the distances and angles on its surface.

Assumptions on Data

The first assumption made on the data is that it is uniformly distributed on the Riemannian Manifold. The second is that the Riemannian metric is locally constant or can be approximated as such. This basically means that if you were to zoom into the manifold and look at a small neighborhood, the points would barely change, if at all. Finally, the last assumption is that the manifold is locally connected. This means that there is no single point floating around on its own and that every point is connected to at least one of its nearest neighbors.

How UMAP Works

UMAP first builds a weighted graph by identifying the k closest neighbors to each data point, like KNN. This graph captures the shape of the data. UMAP then redraws this graph in 2D, using SGD to best retain the neighboring relationship between points. This lower dimensional graph allows you to see possible groupings in the data. You can then refit UMAP with more dimensions than 2, which lets you use it as a tool for dimensionality reduction as well.

Pros and Cons

  • Fast and scalable

  • Works with unsupervised data

  • Works with non linear data

  • Feature extraction, not selection

Small Example: Exploring Customer Shopping Patterns with UMAP

Goal

Imagine a store wants to see whether customers with similar shopping habits tend to behave alike. We have five features for each customer: monthly visits, average spending, online purchases, discount purchases, and returns.

# Load example data
customers <- data.frame(
  customer = LETTERS[1:12],
  visits = c(2, 3, 2, 3, 10, 12, 9, 11, 6, 7, 5, 6),
  avg_spend = c(180, 165, 210, 190, 45, 55, 50, 40, 90, 100, 80, 95),
  online = c(20, 25, 15, 30, 20, 25, 15, 30, 85, 90, 80, 95),
  discounts = c(10, 15, 10, 12, 85, 90, 80, 88, 20, 25, 15, 18),
  returns = c(5, 8, 4, 6, 15, 12, 18, 14, 5, 7, 4, 6)
)

# Hard coded groups, based on how the data was built
customers$group <- rep(
  c("In-store big spenders", "Discount shoppers", "Online shoppers"),
  each = 4
)

group_colors <- c(
  "In-store big spenders" = "#1b9e77",
  "Discount shoppers"     = "#d95f02",
  "Online shoppers"       = "#7570b3"
)

# Select and standardize the customer features
X <- customers %>% select(-customer, -group)
X_scaled <- scale(X)

# Reduce the five features to two dimensions
set.seed(42)
umap_model <- umap(
  X_scaled,
  n_neighbors = 4,
  min_dist = 0.1,
  n_components = 2,
  ret_model = TRUE
)

UMAP takes the five original features and converts each customer into two new coordinates, UMAP1 and UMAP2. This lets us visualize similarities between customers in a two-dimensional plot.

Visualize the results

embedding <- as.data.frame(umap_model$embedding)

plot_data <- data.frame(
  customer = customers$customer,
  group = customers$group,
  UMAP1 = embedding[, 1],
  UMAP2 = embedding[, 2]
)

ggplot(plot_data, aes(UMAP1, UMAP2, color = group)) +
  geom_point(size = 10) +
  geom_text(aes(label = customer), color = "white",
            fontface = "bold", size = 4) +
  scale_color_manual(values = group_colors) +
  labs(title = "Customer Shopping Patterns",
       color = "Shopper type") +
  theme_minimal(base_size = 13) +
  theme(legend.position = "bottom")

Customers appearing near one another have more similar shopping patterns in the original data. The plot can help us identify potential patterns, but UMAP does not automatically assign customers to clusters.

Add a new customer

Suppose we collect data for Customer M. We can use umap_transform() to place this customer into the existing embedding without fitting UMAP again.

# New customer M (same column order as X)
new_customer <- data.frame(
  visits = 4,
  avg_spend = 170,
  online = 22,
  discounts = 12,
  returns = 6
)

# Scale M using the original data's center and scale
new_scaled <- scale(
  new_customer,
  center = attr(X_scaled, "scaled:center"),
  scale = attr(X_scaled, "scaled:scale")
)

# Place M in the existing UMAP space
set.seed(42)
new_embedding <- umap_transform(new_scaled, umap_model)

new_point <- data.frame(
  customer = "M",
  UMAP1 = new_embedding[, 1],
  UMAP2 = new_embedding[, 2]
)

ggplot(plot_data, aes(UMAP1, UMAP2, color = group)) +
  geom_point(size = 10, alpha = 0.45) +
  geom_text(aes(label = customer), color = "white",
            fontface = "bold", size = 4) +
  geom_point(data = new_point, aes(UMAP1, UMAP2),
             inherit.aes = FALSE, shape = 21, size = 12,
             fill = "gold", color = "black", stroke = 1.5) +
  geom_text(data = new_point, aes(UMAP1, UMAP2, label = customer),
            inherit.aes = FALSE, fontface = "bold", size = 5) +
  scale_color_manual(values = group_colors) +
  labs(title = "Adding a New Customer (M)",
       color = "Shopper type") +
  theme_minimal(base_size = 13) +
  theme(legend.position = "bottom")

Customer M can then be added to the plot to see which existing customers they appear closest to.

Why UMAP was useful here

Seeing the structure. Five features per customer is hard to picture, but after UMAP we can see the data in one flat plot. The three shopper types (in-store big spenders, discount shoppers, and online shoppers) each form their own cluster, even though we never told UMAP which customer belonged to which group.

Working with fewer dimensions. Each customer is now described by 2 numbers instead of 5. With only 12 customers this doesn’t save much, but a real store could have millions of customers and hundreds of features. Clustering, searching for similar customers, or plotting is much cheaper on a few coordinates than on the full feature set.

Placing new customers. Because we saved the model, we could add customer M without redoing everything. M landed next to customers A to D, so we can reasonably label M as an in-store big spender. This is a quick way to sort a new customer into a shopper type, for example to decide what kind of offers to send them.

A note on interpretation. UMAP keeps nearby customers close together, but the axes (UMAP1 and UMAP2) have no direct meaning, and distances between far apart clusters should not be over-interpreted. UMAP also does not label anyone by itself. We read the shopper type off of which customers M ended up near.

Applying UMAP to Text Data: Claims Classification

The small example had five features. Real data can have thousands. In this section we use UMAP on the Module 2 claims text data, where each web page is described by 5,367 features, and ask the question that matters most for dimensionality reduction: can UMAP extract a small set of features that still tells the classes apart?

The data

The data are 1,971 scraped web pages, labeled as containing relevant claim content (1,075) or no relevant content (896). We reuse the Module 2 preprocessing to turn each page into TF-IDF weights, giving a matrix of 5,367 word features that is 98.3% zeros. We hold out 20% of the pages (395) for testing and use the other 1,576 for training.

Apply UMAP

We run UMAP twice, using cosine distance because it compares which words a page uses rather than how long the page is. The full code is in scripts/part4-preprocessing.R.

# 2D embedding of every page, for plotting
umap_2d <- umap(tfidf_matrix, n_neighbors = 15, n_components = 2,
                min_dist = 0.1, metric = "cosine")

# 10D embedding fit on training pages only: these are the extracted features
umap_model <- umap(tfidf_matrix[train_idx, ], n_neighbors = 15,
                   n_components = 10, min_dist = 0.1,
                   metric = "cosine", ret_model = TRUE)

# Place the held-out pages into the same 10D space
test_embedding <- umap_transform(tfidf_matrix[test_idx, ], umap_model)

The 2D version is for looking at the data. The 10D version is the feature extraction: it is fit on training pages only, and umap_transform() places new pages in the same space, just like Customer M in the small example. Every page is now described by 10 numbers instead of 5,367.

Visualize the results

UMAP never saw the labels and finds some structure, but the two classes overlap heavily in 2D. A picture alone does not separate these pages. As before, the axes have no direct meaning, and distances between far-apart groups should not be over-interpreted.

Did the extracted features keep the signal?

This is the real test. We predict each held-out page’s class from its 15 nearest training pages (k-nearest neighbors) using three different sets of features.

Features Number of features Held-out accuracy
Always guess the majority class 0 54.4%
All TF-IDF words 5,367 81.0%
UMAP features 10 77.5%
NoteKey takeaway

Ten UMAP features recover most of the accuracy of all 5,367 TF-IDF features (77.5% against 81.0%), and they are far above the 54.4% baseline. UMAP did not classify anything on its own. It produced a much smaller representation of each page that still carries most of the class signal, at a cost of about 3.5 points of accuracy.

Why UMAP was useful here

Feature extraction, not selection. The 10 UMAP features are new coordinates built from all 5,367 words, not a subset of the original words. This is the “feature extraction, not selection” point from the pros and cons list.

Far fewer dimensions. Searching for similar pages or training a model is much cheaper on 10 numbers per page than on 5,367, and the cost is a small drop in accuracy.

New pages can be placed without refitting. Because the model was saved, held-out pages were placed in the existing space with umap_transform(), as in the small example.

A note on interpretation. The 10 features are not individually meaningful, and UMAP can be sensitive to settings such as n_neighbors and min_dist. The 3.5-point gap to the full TF-IDF features is also worth noting: the extracted features are a compressed summary, not a lossless one.
